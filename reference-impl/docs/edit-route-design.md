# 剪輯路線 (edit route) 設計：素材 → 剪輯表 → 出片

使用者 2026-10-18 的方向：把 lab 收斂成 agent 主導的剪輯／製作／生成流程，第一個生成接口接本機 ComfyUI；生成素材和現成影片**另開剪輯路線**，不等時間軸層的編譯器 (TL-1)。提案單：`~/.claude/outputs/agent-led-video-pipeline-20261018/提案單_agent主導影片製作流程_20261018.md`。

## 一、和既有工具的關係

| 路線 | 輸入 | 出片 | 用在 |
|---|---|---|---|
| 程式畫面（既有） | 一個 `__setTime(t)` 頁面 | `filmkit render` | 動態圖像、文字動態、資料片 |
| 時間軸層（既有，TL-0） | `film.timeline.json` | TL-1 編譯器（未建） | 有旁白、分段的程式畫面片 |
| **剪輯路線（新）** | 已登記的素材＋剪輯表 (EDL) | `tools/edit` 以 ffmpeg 組合，再跑 `filmkit check` | 生成素材、實拍或錄影片段、把程式畫面成品當一段 |

- 時間軸層設計 §0.3 的「不用生成式影片模型」仍然只管時間軸層本身；生成素材走這條路線（該節加註）。
- filmkit 不改：剪輯路線只呼叫 `check.py` 取得同一套事實（長度、尺寸、幀率、音軌、響度、1 fps 縮圖）。

## 二、三個契約

1. **素材登記＋出處 (provenance)**：每個素材 `assets/<id>.<ext>` 旁邊都有 `assets/<id>.provenance.json`，內容包括 sha256、來源類型、建立時間、建立工具：
   - `footage`（現成影片）：另記原始位置、授權
   - `generated`（生成）：另記 provider、model、prompt、seed、參數、花費、job id、adapter 版本、輸入素材的雜湊
   - `motion`（程式畫面成品）：另記頁面路徑和 filmkit `render.json` 的雜湊

   出片前會逐一核對雜湊和必填欄位，不符就拒絕出片並寫出是哪個素材。
2. **剪輯表**：採業界交換格式 OpenTimelineIO（`.otio`，0.18.1），之後可以帶進 DaVinci Resolve、Premiere 這類軟體。
   - 第一版：一條影軌（片段或空白）＋一條音軌（配樂）。
   - 時間一律用整數格數，因此切點一定落在格線上。
3. **生成接口 (adapter)**：`generate(request) → asset + provenance`。
   - `mock`：用 seed 決定的合成片段，供測試用。
   - `comfyui`（P3，2026-10-18 已接上）：本機 0.25.1，RTX 5070 筆電版 8 GB；用你自己 Klein 工作流程裡的 FLUX.2 klein 4B 蒸餾版，產生 1280x720 的圖約 8 秒（第一次載入模型 27 秒）。
   - 目前只能產生圖：本機還沒有影片模型，所以剪輯時圖是靜止的。

## 三、照拍點剪輯 (P2)

- **做法**：配樂 → `beatgrid` 的拍點網格（`bpm`、`period_s`、`phase_s`）→ 每 N 拍切一刀 → 剪輯表 → 出片。
- **驗收**：用 `beatgrid` 量成品的切點和音樂拍點的距離（儀器限制寫在它的輸出裡），要求中位數在 1 格以內。
- **反向對照**：故意把切點平移半拍，中位數必須明顯變大；變大了才代表這個量測真的量得到差異。

- **使用者看完示範片的判定（2026-10-18）**：「論節拍都在點上，大概就是標準的穩定，但『不是最適合的依賴方式』我認為（跟其他影片的製作通病有關）」。
  - 因此照拍點剪輯只是**基準工具與限制條件**，不是決定切點的預設依據。切點應該跟著內容與畫面狀態走（要說什麼、狀態何時改變），拍點只用來把切點對齊到最近的拍上。
  - 接下來的做法見提案單〈影片製作通病〉。

## 四、不做（這一版）

不做疊字／轉場特效（硬切以外只有溶接，而且溶接最先砍）、不做審片迴圈 (P4)、不做 GUI、不判斷好不好看（INV-6）。
