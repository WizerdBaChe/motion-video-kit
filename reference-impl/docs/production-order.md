# 製作單節點草圖

2026-09-29 起草。使用者的方向：**正式版的製作流程，會是填一張製作單 (production order)**，這張單由已經相對穩定的 workflow 對應出來。現在還在研究階段，所以這份文件的工作是**把節點盡量補齊**。哪些欄位必填、怎麼標註、怎麼寫，都等之後再決定（見最後一節）。

這份文件把三件事接在一起：

- 每個節點目前有多少證據（技巧卡、量測工具，或只是案例作者的說法）。
- **運鏡**要拆成「目標」和「製作方式」兩層來記。
- **分鏡紀錄**的欄位：原片、模仿組、成品三邊用同一套欄位，才能逐段對照。

2026-09-29 試填過一次：C21 40 s 原片和 r9 B1 各填一張分鏡紀錄，運鏡先看畫面標、再讀程式核對。結果見 [shot-record-trial.md](shot-record-trial.md)，下面的表已照結果改過。

來源：這個實驗室的 T01–T07、`docs/workflow.md`，以及 reelmimic（github.com/edenfunf/reelmimic @ d622540）。reelmimic 是一個「給參考片，做同風格新片」的工具，這裡只借它三個做法：逐鏡對應欄位、審查收斂規則、運鏡量測。借來的部分標〔reelmimic〕，**都還沒在這裡實測過**。

## 證據狀態標記

| 標記 | 意思 |
|---|---|
| 〔已驗證〕 | 有技巧卡＋校準過的工具，而且模仿實測裡兩組範圍不重疊 |
| 〔已量〕 | 有校準過的工具，在案例上量過，但還沒有 A/B 實測 |
| 〔說法〕 | 案例作者的說法或教學內容，這裡沒量過 |
| 〔試填〕 | 在真的片上填過或標過，對照過程式，但只有讀者判讀、n 很小 |
| 〔你看片〕 | 你看過實測片後的判讀；沒有工具，n 很小，但它是「好不好看」唯一的依據 |
| 〔reelmimic〕 | 從 reelmimic 借來的做法，這裡沒測過 |
| 〔缺〕 | 知道要有這個節點，但還沒有證據、也沒有工具 |

## 運鏡：目標和製作方式分開記

同樣是「推近」，拿來做什麼、用什麼方法做，會決定它該怎麼寫進製作單，也決定量出來的數字能不能比。所以運鏡要拆成兩層。

**光流 (optical flow) 只看得到螢幕上的總動作**：它分不出是整個舞台縮放、3D 攝影機在飛，還是內容自己在動。這個實驗室已經碰過兩次：

- T02：元件彈簧要照螢幕座標算。另外疊一條鏡頭縮放，成品就變慢。
- T04：`segments.py` 分不出「換段」和「段內推近」，C08 14.9 s 的推近被算成一次換段。

所以「目標」和「製作方式」要由人看（或讀成品的程式）來標，工具只負責量種類和快慢。

### D1. 運鏡目標（這個運鏡是為了什麼）

| 值（暫定） | 意思 | 案例 |
|---|---|---|
| 帶視線到主角 | 推近或甩鏡後停在要講的東西上，常搭配景深模糊 | C09 11.4–14.8 s 推近到結果列、其他海報模糊；C01 甩鏡停下的地方就是主角；r9 A1 16 s 地圖推近到離島 |
| 換段 | 運鏡本身就是轉場 | C11 一段一座島、鏡頭飛行換段；C01 6.1 s 模糊推近進到下一段，C01 的換段方式整支都是 iris、甩鏡、推近（T04 全片結構表） |
| 展示產品畫面 | 截圖或網站畫面被傾斜、推入，讓靜態畫面有動感 | C21 8.0–9.8 s 網站首頁卡 3D 傾斜推入；T07 功能段；r9 B 組 3/3 照抄（A 組 0/3） |
| 開場帶入 | 從全景推到第一個操作點 | C09 0–7.2 s 首頁推近到搜尋框 |
| 氛圍 | 很慢的漂移，不帶任何資訊 | r9 B1 4–8 s 品牌字每秒放大約 1.2%（程式核對）；C21 4–8 s 漂浮卡看起來是同一種，原片沒有程式 |

### D2. 運鏡製作方式（用什麼做出來）

| 值（暫定） | 意思 | 量測時要注意 |
|---|---|---|
| 2D 舞台變換 | 整個舞台一起 `scale`／`translate` | 元件動態和鏡頭動態在螢幕上疊加（T02） |
| 平面卡片 3D 透視 | 一張截圖或卡片加 `perspective` 傾斜推入 | 光流會同時看到縮放和旋轉 |
| 3D 場景攝影機 | 真的 3D 場景，攝影機在裡面飛 | 視差 (parallax)：前景和背景速度不同，光流不是單一值 |
| 單一圖層的鏡頭 | 只有一層（例如地圖）推近或平移，標題等其他元件不動 | 從畫面分得出來（其他元件不跟著動）；r9 A1 地圖焦點縮放 |
| 素材本身的運鏡 | 生成影片或實拍自帶的鏡頭動作 | 不是程式控制的，只能照原樣剪 |

**不是運鏡**：運鏡是對一個裝了兩個以上不相干元件的容器做變換。下面這些是元件動態，不填 D1／D2：元件自己放大當成擦除式轉場（r9 A1 3 s Logo、B1 14 s 長條、B1 21 s 數字放大＋模糊）、翻牌數字的 `rotateX`。從畫面看，這三處都被我誤標成運鏡；有程式時以程式為準。

D1 已經寫進案例分類的 `camera` 軸（你 2026-09-30 裁定；`none` 表示沒有運鏡，見 `docs/taxonomy.md`）。D2 製作方式仍是暫定值，不收進分類軸。

## 分鏡紀錄的欄位

同一套欄位用在三個地方：

1. **原片的鏡頭表**：第一輪解析時由我看縮圖表填；有工具的欄位用工具的數字。
2. **模仿組或製作端的計畫**：每一段都指回原片的哪一段（`ref_seg`），以及借了那段的什麼（`ref_what`）。
3. **成品的量測**：用同一支工具量，和原片逐段並排。

reelmimic 的做法是：計畫裡每一鏡都寫 `ref_shot`，做完再用同一套量測把參考鏡頭和成品鏡頭並排。這裡目前的比較（`tools/compare.py`）是整支片對整支片。試填 r9 B1 時事後補 `ref_seg`：13 段有 8 段指得回原片，「照抄了多少」變成可以數的東西（[shot-record-trial.md](shot-record-trial.md) §2）。

| 欄位 | 內容 | 值從哪來 |
|---|---|---|
| `seg` | 段落編號（S1、S2…） | — |
| `t` | 起訖秒數；有音樂時也寫拍數 | 工具（`segments.py`）或眼看 |
| `headline` | 畫面上的主標題（試填後新增） | DOM 文字（`fidelity.py`）或眼看 |
| `visual` | 視覺語法：地圖、計數、強調長條、3D 卡牆、手機聊天……（試填後新增；T07 的 variety 就是這一欄） | 眼看 |
| `motion_intent` | 這段每個會動的元件（和疊上去的每層效果）各一句「這個動作在說什麼」；老梗手法一定要填（見 E. 動態）（2026-10-01 新增） | 計畫時填；原片眼看推測，標「推測」 |
| `data` | 這段講的資料點和來源欄位（試填後新增） | `measure_showreel.py`、`fidelity.py` |
| `layout` | 版面分區，例如標題左、圖右（試填後新增；T04 骨架寫在這裡） | 眼看；`segments.py --crop` 驗標題區 |
| `what` | 補充說明（選填；有了 `headline`、`visual` 之後只剩補充） | 眼看 |
| `driver` | 節奏跟著什麼。**放在全片一格**，個別段落不同時才另填（試填：兩支片 13 段都一樣） | 工具或眼看 |
| `transition_in` / `transition_out` | 進場、出場的轉場，加上長度 `dur` | 眼看；長度用 `segments.py` 的 `run_s` |
| `camera.move` / `camera.pace` | 推近、拉遠、平移、旋轉、靜止；快慢。`pace` 一秒一格看不出來，等運鏡量測工具 | 候選工具，目前眼看 |
| `camera.goal` | D1 的值 | 眼看 |
| `camera.method` | D2 的值 | 讀程式；原片只能眼看，小元件標「可信度低」 |
| `sound` | 轉場音效（試填後新增） | 模仿組讀配樂程式；原片寫「無法驗證」 |
| `ref_seg` | 對應原片的第幾段（原片本身留空） | 計畫時填 |
| `ref_what` | 借了那段的什麼手法 | 計畫時填 |
| `src` | 每個數字標「工具名」或「眼看」 | — |

**模仿實測要注意一件事**：workflow ⑤ 已經學到「框架給了什麼，那一項就測不出卡片的效果」。所以不要把「每段要填 `ref_seg`」直接加進現有的框架（`rounds/frame_*.md`）：

- 事後逐段對照：由我在 ⑥ 補填模仿組的 `ref_seg`。
- 想測「逐段對應寫進計畫會不會更像」：把它當成一個獨立的條件，另外開一輪 A/B。

## 載體與必填（你 2026-10-08 裁定，見 `docs/timeline-layer-design.md` §12 D-T8）

原本留待之後決定的四項，已隨時間軸層設計定案：

- **載體**：JSON 時間軸檔 `film.timeline.json`，由對話填寫；給人看的是由它生成的唯讀時間軸頁（D-T3）。
- **必填**：整片決策的片型、能量、受眾、節奏來源；每個片段的時間（`at`、`dur`）、自由度、動作意圖。其餘可留空，空著的由模型依最字面解讀補上並標「模型定的」。
- **標註的寫法**：D1 運鏡目標、D2 製作方式成為 `camera.goal`／`camera.method` 的固定詞彙表；分鏡紀錄的欄位對應到時間軸片段的欄位；名稱有改的列在 `docs/timeline-layer-design.md` §6.1 對照表。
- **升成預設值**：節點對應的元件到〔已量〕以上，才成為製作單的預設值。
